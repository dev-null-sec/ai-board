# 当前状态

> 给下一次 AI 或人类开发者快速接上上下文用。保持短、准、新。

## 项目一句话

`ai-board` 是一个轻量本地 CLI，用 JSON 作为唯一真相源，为 AI 开发提供任务入池、排期、scope 约束、验收、归档、冲突检查和本地治理护栏。

## 当前能力

## 当前风险 / 未决问题

- CLI 目前是最小版，暂未提供复杂依赖关系检查；锁能力仍是轻量 JSON 级 scope lock，不是 OS 文件锁。
- 0.2 git scope gate 已把 scope 检查推进到提交前 staged diff 关口，但它仍不是运行时文件拦截或安全沙箱；标准 Git 仍可用 `--no-verify` 绕过本地 hook，严肃项目后续应在 CI 或发布检查里再跑 gate。
- 流程教训：重要方向不能只落成一句 current goal 或聊天结论。后续确认版本路线、1.0 定义、能力边界或长期取舍时，必须同步 `docs/决策记录.md`、`docs/项目路线/` 路线文档和 `.ai-board/board.json` 需求池。
- Markdown 是生成视图，后续需要在 README 和规则中反复强调不要手改生成看板。
- 冲突检测只覆盖路径重叠，不做语义级代码冲突判断。
- scope 颗粒度暂不引入 glob 或文件级锁；当前策略是保留路径前缀冲突算法，在多 agent 开启时用于路径级防撞，并通过 `doctor` 和 AI 使用指南提醒 agent 避免锁住过大的根目录。
- 存储后端已完成评估：默认继续使用 `.ai-board/board.json`；后续如果需要历史追踪，优先做可选 `.ai-board/events.jsonl` 事件日志；SQLite 暂缓到复杂查询、跨项目聚合或高频并发写入需求明确后再评估。
