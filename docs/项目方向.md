# 项目方向

## 项目目标

做一个轻量、可开源的本地 CLI 项目，为 AI 协作开发提供“唯一真相源”的计划看板。

它要解决的问题是：多 agent 或长会话开发时，任务状态、负责人、验收结果、归档记录容易散落在聊天和 Markdown 里，导致冲突、重复开发和进度丢失。

## 目标用户

- 使用 AI/Codex/Claude Code 等工具开发项目的个人开发者。
- 想尝试多 agent 协作，但需要任务锁、范围声明和冲突检查的开发者。
- 想把计划看板放进 Git 仓库、并让 AI 能稳定操作的开源项目维护者。

## 初版范围

- 使用 `.ai-board/board.json` 作为唯一写入源。
- 提供 CLI 完成任务生命周期：`init -> add -> schedule -> start -> complete -> archive`。
- 支持 agent claim、scope 文件范围、验收记录和遗留问题。
- 支持简单冲突检测：活跃任务之间的文件/目录 scope 重叠。
- 自动渲染 `docs/计划看板.md` 和 `docs/归档计划看板.md` 给人和 AI 阅读。
- 提供一个 `examples/demo-project` 示例项目验证 CLI 效果。
- 提供可安装的 Codex skill，让 AI 通过 skill 学会使用 `ai-board` CLI。
- CLI 需要能作为终端命令直接运行，适合 AI 和人类开发者共同使用。

## 暂不做

- 不做 Web 登录系统。
- 不做 Jira 式复杂项目管理。
- 不做自动智能排期。
- 不做多人权限和云同步。
- 不引入第三方运行时依赖。
- 不把 Markdown 当作写入源。
- 不把主要使用说明长期写死在 skill 里导致版本过期；skill 应尽量作为入口，引导 AI 使用随 CLI 版本维护的说明。

## 成功标准

- 从空目录可以初始化 board。
- 可以新增、排期、开始、完成、归档一个任务。
- 可以检测两个活跃任务的 scope 冲突。
- Markdown 看板可以从 JSON 自动生成。
- 单元测试通过。
- README 能让 GitHub 用户理解用途和快速试用。
