# 规划意图持久化与阶段路线检查

## 背景

ai-board 目前能把单个任务的状态、scope、验收和归档记录下来，但还缺一层对“长期规划意图”的约束。

实际协作中常见的问题是：

1. 用户和 AI 已经讨论出长期方向，例如先做文档，再做 skill 规范，最后做 CLI。
2. AI 为了先推进一小块，只把“文档落地”排进看板。
3. 当前批任务做完后，需求池被清空。
4. 下一轮 AI 看不到后续阶段，只能从聊天记录、目录名或当前文件猜下一步。

这违反 ai-board 的基本原则：关键项目状态不能只留在聊天记录里。

## 判断

这个问题不应该直接用复杂项目管理系统解决。ai-board 仍然保持轻量，本轮只补一条规则：

> 可以只排期当前阶段，但不能丢掉已知后续阶段。

也就是说，AI 不必一次性把长期路线拆成几十个任务；但只要已经形成了阶段判断，就必须把后续意图落到项目文件里。

## 三层结构

ai-board 后续规划应区分三层：

| 层级 | 放在哪里 | 作用 |
| --- | --- | --- |
| 方向层 | `docs/项目路线/`、`docs/当前状态.md`、`docs/决策记录.md` | 记录长期目标、路线原则和关键取舍 |
| 阶段层 | 路线文档里的 phase/阶段列表，或需求池中的占位任务 | 记录“当前只做一部分，后面还有什么” |
| 任务层 | `.ai-board/board.json` | 可 start、complete、archive 的具体工作 |

任务层不能替代方向层。反过来，路线文档也不能替代正在执行的任务。

## 规划后的最低记录要求

当用户让 AI 做“规划、排期、大方向、先 A 再 B、分阶段推进”这类工作时，AI 必须留下下面四类信息：

1. 长期方向：这轮共识到底是什么。
2. 阶段拆分：至少列出当前阶段和已知后续阶段。
3. 当前只排期范围：为什么只排当前这批任务。
4. 后续待拆：哪些阶段暂不展开，但不能丢。

推荐格式：

```text
长期方向：
阶段 1：
阶段 2：
阶段 3：
当前只排期：
暂不排期但已知后续：
```

这些内容至少要进入以下位置之一：

- `docs/项目路线/*.md` 的路线或方案文档；
- `.ai-board/board.json` 的需求池占位任务；
- `docs/当前状态.md` 的“下次接手建议”。

如果后续阶段已经足够清楚，优先放入需求池占位任务；如果还很粗，先放路线文档的“后续待拆”。

## next / doctor 的后续设计

后续可以在 `next` 和 `doctor` 增加轻量提醒，但不在 0.3 前强制实现复杂 roadmap 状态机。

### next

建议规则：

- 当 active、scheduled、inbox 都为空；
- 且 `docs/项目路线/` 中存在明确的“后续待拆 / 下一阶段 / phase”未完成条目；
- `next` 提示：当前看板没有候选任务，但路线文档仍有后续阶段，请先从路线文档拆下一批任务。

### doctor

建议规则：

- 当 board 当前目标或路线文档包含长期阶段；
- 但需求池、下一批和当前状态都没有对应占位；
- `doctor` 给出 warning，不直接失败。

这条检查只做“防断档提醒”，不判断路线内容是否正确。

## 不做什么

- 不引入独立 milestone 数据模型。
- 不做甘特图、燃尽图或复杂依赖规划。
- 不要求 AI 一次性拆完所有未来任务。
- 不把路线文档变成第二个任务数据库。
- 不根据自然语言自动推断阶段完成状态。

## 最小落地范围

第一步只做规则和设计落地：

- 更新 `ai-board skills get core`：规划后必须保存后续意图。
- 更新 `docs/开发规范.md`：排期不等于只排眼前任务。
- 增加回归测试，防止 guide 以后删掉这条规则。

后续如果要实现命令或检查，再单独排期：

- `next` 路线断档提醒。
- `doctor` 路线占位检查。
- 可选的 `roadmap` 或 `plan` 辅助命令评估。

## 测试矩阵

| 场景 | 期望 |
| --- | --- |
| core guide 输出 | 包含“不要只把后续阶段留在聊天里”的规则 |
| full guide 输出 | 包含规划、阶段、后续待拆的详细说明 |
| 开发规范 | 明确长期规划需要同步路线文档或需求池占位 |
| 路线文档 | 明确 next/doctor 只做轻量提醒，不做复杂项目管理 |
