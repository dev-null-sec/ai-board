# 0.2 git scope gate 规格

## 结论

0.2 的目标不是把 `ai-board` 做成文件系统安全沙箱，也不是让它在运行时拦截 AI 写文件。

0.2 要补的是一个更现实、更有用的关口：**在 git commit 前检查 staged diff 是否落在当前 active task 的 scope 内**。这把 scope 约束从 `doctor` 的事后发现，推进到提交前的可提示、可阻断。

默认仍保持轻量：不在 `init` / `onboard` 时静默安装 hook，不覆盖用户已有 hook，不强制单 agent 小项目承担团队流程成本。

## 范围

0.2 做：

- 新增项目配置 `scope_gate=off|suggest|required`。
- 新增 staged diff 与 active task scope 的覆盖检查。
- 新增 hook 安装、状态检查、卸载入口。
- 让 pre-commit hook 调用同一套 gate 检查。
- 让 `doctor` 能提示 gate 配置与 hook 状态不一致。
- 补 README、CLI guide、CHANGELOG 和回归测试。

0.2 不做：

- 不做运行时文件写入拦截。
- 不做权限系统或安全沙箱。
- 不做语义级代码冲突检测。
- 不切换 SQLite。
- 不默认开启多 agent 协作。
- 不把 verification evidence 并入 0.2；它留给 0.3 评估。

## 配置

新增 `.ai-board/config.json` 字段：

```json
{
  "scope_gate": "suggest"
}
```

行为：

| 值 | 行为 | 适合场景 |
| --- | --- | --- |
| `off` | 不运行 scope gate。`doctor` 不提示 hook 状态。 | 轻量个人项目、迁移期 |
| `suggest` | 发现越界时输出 warning，但 hook 返回 0，不阻断 commit。 | 默认推荐值 |
| `required` | 发现越界时 hook 返回非 0，阻断 commit。 | 严肃项目、多人或多 agent 协作 |

0.2 可以把新项目默认值设为 `suggest`，但不自动安装 hook。这样用户能看到能力和提示，又不会被静默接管 git 流程。

## gate 检查对象

gate 只检查 git staged diff：

```text
git diff --cached --name-status
```

不检查整个工作区，原因是 pre-commit 只应该约束“本次准备提交什么”，不应该因为工作区里还放着草稿文件而阻断提交。

路径处理规则：

- `A` / `M` / `T`：检查当前路径。
- `D`：检查被删除路径。
- `R` / `C`：同时检查旧路径和新路径；重命名本身也必须落在任务范围内。
- 路径统一走现有 scope 规范化逻辑，避免 `src/api` 与 `src/apix` 的前缀误判。
- scope `.` 代表整个项目，覆盖所有业务路径。

## scope 覆盖规则

对 staged diff 中的每个业务路径：

1. 找出所有 `active` 且 scope 未过期的任务。
2. 如果没有 active 任务，业务路径视为未覆盖。
3. 如果路径落在任一 active task scope 内，视为覆盖。
4. 如果路径不在任何 active task scope 内，视为越界。

0.2 先不强制“必须属于当前 agent 的 active task”。原因是当前项目还没有稳定的本地 current-agent 机制，直接做 owner 绑定容易误伤。后续如果实现 `agents current`，可以再增加 stricter 模式。

## ai-board 记账副作用

下面这些路径属于 `ai-board` 自身的记账或生成副作用，不要求写进业务 task scope：

```text
.ai-board/board.json
.ai-board/events.jsonl
.ai-board/messages.jsonl
.ai-board/config.json
docs/计划看板.md
docs/归档计划看板.md
```

处理规则：

- gate 覆盖检查时忽略这些路径，不把它们判为越界。
- 如果一次提交只有这些记账副作用，gate 通过。
- 如果生成 Markdown 和 board 状态不一致，由 `doctor` 负责发现；scope gate 不重复承担 stale render 检查。
- 如果任务本身就是修改 ai-board 源码、README、CHANGELOG、测试或 docs，这些仍是业务路径，必须进入 task scope。

## CLI 入口

建议新增：

```text
ai-board gate pre-commit
ai-board hooks install pre-commit
ai-board hooks status
ai-board hooks uninstall pre-commit
```

`ai-board gate pre-commit`：

- 读取 `scope_gate`。
- 读取 staged diff。
- 输出 uncovered paths、active tasks、修复建议。
- `off` 总是返回 0。
- `suggest` 有问题也返回 0。
- `required` 有问题返回 1。

修复建议要直接可执行：

```text
Run: ai-board start TASK_ID --scope path/to/file
or:  ai-board rescope TASK_ID --agent AGENT --scope ...
or:  split this commit so each change belongs to an active task
```

`ai-board hooks install pre-commit`：

- 只在 git 仓库中可用。
- 如果 `.git/hooks/pre-commit` 不存在，写入 ai-board 托管 hook。
- 如果 hook 已存在且带 ai-board managed marker，可以更新。
- 如果 hook 已存在但不是 ai-board 托管，不覆盖；输出手动合并片段。

`ai-board hooks uninstall pre-commit`：

- 只删除 ai-board 托管 hook。
- 遇到用户自有 hook 时不删除，只提示人工处理。

`ai-board hooks status`：

- 显示 `scope_gate` 当前值。
- 显示 pre-commit hook 状态：missing、managed、foreign、unknown。
- 显示 required 模式下是否会被 `doctor` 判为 issue。

## doctor 规则

新增 doctor 检查：

| 条件 | 结果 |
| --- | --- |
| `scope_gate=off` | 不检查 hook |
| `scope_gate=suggest` 且 hook 缺失 | notice，不失败 |
| `scope_gate=suggest` 且 hook 是 foreign | notice，提示不会自动接管 |
| `scope_gate=required` 且非 git 仓库 | issue |
| `scope_gate=required` 且 hook 缺失 | issue |
| `scope_gate=required` 且 hook 是 foreign | issue，提示人工合并 |
| `scope_gate=required` 且 hook managed | ok |

这条规则和 `git_integration` 分工不同：

- `git_integration` 管“项目是否应该使用 git”。
- `scope_gate` 管“提交前是否检查 task scope”。

## 输出口径

文案必须克制：

- 可以说：`scope gate checks staged files before commit`。
- 可以说：`required mode rejects commits with files outside active task scope`。
- 不说：`ai-board prevents AI from editing files`。
- 不说：`ai-board is a security boundary`。

README 和 CLI guide 要明确：标准 Git 仍允许用户用 `--no-verify` 绕过 hook；这不是漏洞，而是 git 的设计。严肃项目应在 CI 里再跑 `ai-board gate pre-commit` 或等价检查。

## 测试矩阵

| 场景 | 期望 |
| --- | --- |
| `scope_gate=off` | gate 总是返回 0 |
| `scope_gate=suggest` 越界 | 输出 warning，返回 0 |
| `scope_gate=required` 越界 | 输出 issue，返回 1 |
| 无 staged diff | 返回 0 |
| 无 active task 且有业务改动 | suggest warning / required fail |
| active scope 覆盖业务路径 | 返回 0 |
| active scope 不覆盖业务路径 | suggest warning / required fail |
| scope `.` | 覆盖所有业务路径 |
| `src/api` vs `src/apix` | 不误判为覆盖 |
| delete 文件 | 用删除路径做覆盖检查 |
| rename 文件 | 旧路径和新路径都要覆盖 |
| 只提交 `.ai-board/board.json` 和生成看板 | 返回 0 |
| 业务改动加 ai-board 记账副作用 | 只检查业务改动 |
| hook 不存在时 install | 写入 managed hook |
| hook 已有且 foreign | 不覆盖，输出合并提示 |
| required 模式 hook 缺失 | doctor fail |
| suggest 模式 hook 缺失 | doctor notice |
