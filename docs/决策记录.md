## 记录

## 2026-05-13 使用 JSON 作为 v1 唯一真相源

- 背景：项目需要给 AI 和人一个稳定可操作的看板源，避免直接手写 Markdown 导致状态漂移。
- 选择：v1 使用 `.ai-board/board.json` 作为唯一写入源。
- 不选择：暂不使用 SQLite 作为默认存储。
- 原因：JSON 更轻，Git diff 友好，用户能手工修复，适合开源项目早期验证。
- 影响：后续如果出现并发写入、复杂查询、事件流审计需求，再评估 SQLite 后端。

## 2026-05-13 Markdown 只作为生成视图

- 背景：计划看板需要给人和 AI 阅读，但直接修改 Markdown 容易破坏结构。
- 选择：`docs/计划看板.md` 和 `docs/归档计划看板.md` 由 CLI 从 JSON 渲染。
- 不选择：不把 Markdown 当作状态写入源。
- 原因：保持单一真相源，减少多 agent 并行时的冲突。
- 影响：用户若手改生成的 Markdown，下次 `render` 会覆盖这些改动。

## 2026-05-13 v1 保持无第三方运行时依赖

- 背景：项目准备开源，初版应该容易试用和审查。
- 选择：CLI 使用 Python 标准库实现。
- 不选择：暂不引入 Typer、Rich、Textual、SQLite ORM 等依赖。
- 原因：降低安装门槛，减少维护复杂度。
- 影响：CLI 输出保持朴素；后续如果体验不足，再按需引入依赖。

## 2026-05-13 采用 skill + CLI 的分发形态

- 背景：用户希望项目像 `agent-browser` 一样，让用户安装 skill 后，AI 能通过 skill 学会调用终端 CLI。
- 选择：后续优先实现“轻量 skill 作为 AI 使用说明书 + 可直接运行的 `ai-board` CLI”。
- 不选择：不把所有命令说明长期硬编码在 skill 里。
- 原因：CLI 和 skill 分离后，AI 有稳定入口，人类也能在终端直接操作；同时可以减少 skill 内容过期。
- 影响：`T-0004` 作为 P0 排到下一批最前面，优先于普通开源材料补齐。
